# [ORGANISATION] — ISO/IEC 42001:2023 Statement of Applicability and clauses 4–10 checklist — TEMPLATE

> [!TIP]
> **How to use this template.** Blank reusable template. Prepared by Olugboye Shola. All 38 Annex A controls are pre-filled with their
> IDs, short titles and a paraphrase of what each asks; obtain the standard for the full requirements. Decide
> applicability first, then score maturity, then let the status follow from the maturity.

## Rules to set before scoring

| Rule | Default |
|---|---|
| Maturity scale | 0 none · 1 initial / fragment · 2 approved but unevidenced · 3 implemented with evidence · 4 measured and improved |
| Status | **Derived, never typed:** 0 = Not started · 1–2 = Partial · 3–4 = Implemented |
| The restraint rule | An approved but unevidenced control is a **2**. It can never be Implemented |
| Exclusions | Every "N" needs a reason **and a trigger** that brings it back into scope |
| Deployer-only organisations | A.6 and A.7 (building AI) are often excluded; keep verification, deployment, operation and event logs (A.6.2.4, A.6.2.5, A.6.2.6, A.6.2.8) in, because they apply to anyone who puts AI into use |

## Readiness score

| Component | Calculation | Weight |
|---|---|---|
| Clauses | sum of scores ÷ (2 × 30) | 60% |
| Annex A | (Implemented + 0.5 × Partial) ÷ applicable controls | 40% |
| Gate override | Any gate below 2 = **NO-GO**, whatever the percentage | — |
